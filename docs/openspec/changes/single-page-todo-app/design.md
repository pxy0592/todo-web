## Context

仓库目前没有应用代码或前端工具链；本变更因此需要建立最小可运行的浏览器端页面。设计需满足 `proposal.md` 与 `specs/todo-management/spec.md` 的行为契约，同时避免把任务操作、存储和 DOM 展示耦合在一起。

## Goals / Non-Goals

**Goals:**

- 提供无需后端即可运行的单页 Todo 应用。
- 让任务模型和用例操作可独立测试，并为筛选、优先级等字段留下扩展点。
- 在浏览器刷新后可靠恢复可识别且有效的任务数据。

**Non-Goals:**

- 不实现用户账户、跨设备同步、服务端 API 或数据库。
- 不在本变更中实现筛选、优先级、编辑、排序或批量操作。

## Decisions

1. **采用原生 HTML、CSS 和 JavaScript。** 当前仓库没有框架、构建工具或依赖；原生实现可直接由静态服务器提供，避免为简单单页功能引入不必要的运行时。若未来规模显著增长，可在保持任务用例契约的前提下迁移到框架。

2. **按职责拆分为模型/用例、存储适配器和 UI 层。** 建议结构为 `src/todo/model.js`（任务形状与纯操作）、`src/todo/storage.js`（`localStorage` 读写与校验）、`src/todo/ui.js`（渲染与事件绑定）及 `src/main.js`（组装初始化）。UI 只调用任务操作并在变更后持久化，未来筛选或优先级可作为模型字段和独立展示/查询逻辑加入。

3. **使用带版本的数组存储格式。** 每条任务包含 `id`、`text`、`completed`，存储值使用 JSON 包装对象，例如 `{ "version": 1, "tasks": [] }`。ID 在创建时生成并用于 DOM `data-task-id`，删除和切换状态按 ID 定位而非按数组索引，避免列表扩展时产生误操作。

4. **对输入和存储数据采取 fail-safe 策略。** 创建前 trim 文本并拒绝空值；读取时捕获 JSON 解析异常，并过滤缺少有效 ID/文本/布尔状态的记录，无法识别的数据按空列表处理。写入失败不应阻止当前页面内存状态继续工作；可在 UI 中提供非阻塞错误提示。

5. **使用原生表单语义和委托事件。** 输入使用 `<form>` 支持点击提交和 Enter，复选框与按钮提供可访问名称；列表容器使用事件委托，以便动态任务行无需逐项重复绑定监听器。完成样式通过语义化 class 或属性驱动，包含 `text-decoration: line-through`。

## Risks / Trade-offs

- [localStorage 不可用或空间不足] → 捕获读写异常，保留当前会话状态并显示简短提示；不引入后端兜底。
- [直接渲染用户文本导致 HTML 注入] → 使用 `textContent` 创建任务文本，禁止将用户输入拼接进 `innerHTML`。
- [原生工具链缺失导致测试难启动] → 同步建立最小开发/测试脚本，并在 README 中记录运行方式。

## Migration Plan

首次部署为静态文件即可。若未来替换存储格式，读取器按 `version` 分支迁移旧数据并在成功后写回新格式；若本变更回滚，删除新增静态资源即可，不影响任何服务端数据。

## Testing Strategy

为模型/存储适配器编写单元测试，覆盖添加、空白输入、完成切换、按 ID 删除、序列化/恢复和无效数据；使用浏览器端集成测试覆盖页面加载、刷新恢复和核心按钮交互。测试应对应规格中的每个场景。
